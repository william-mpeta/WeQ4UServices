# Base44 prompt: founder review visual

Paste this prompt into the WeQ4U Base44 workspace to create a presentation view for founder discussion. Treat the local HTML visual in this folder as the content reference.

> Create a responsive, presentation-ready WeQ4U founder review visual called “One service journey, three connected design views”. This is a product and architecture proposal, not a production dashboard. Use an isometric three-layer platform illustration: (1) Business & Workflow, (2) Information & Database, and (3) Customer/Staff Channels & Technology. Use a calm dark-green, cream and amber palette with clear typography and a print-friendly layout.
>
> Show two visibly distinct labels: “Prototype today” and “Target design / approval”. Prototype today: customer intake with service-specific questions and document upload, reference-based tracking, staff dashboard, role-based API tokens, operational filters and CSV export; request records currently live in encrypted local development storage. Target design: PostgreSQL source of truth, versioned workflows, tasks, status events, document review, individual staff identity, scoped permissions, audit, and reliable reporting. Do not imply these planned items are already implemented.
>
> Draw the customer journey as seven connected steps: Enquiry → Documents → Verify & Quote → Customer Approval → Payment Gate (timing/model to be confirmed) → Fulfilment → Completion. Add owner labels to each step. State that customers should be able to see their status and next action without calling.
>
> Add a database starter section showing: customers → service_requests → request_services; documents and reviews; workflow_instances → tasks → events; quotes → quote_lines → quote_decisions; payment orders/transactions; staff, departments, notifications, audit, and retention records. Explain that PostgreSQL stores structured records and metadata, while document bytes belong in private object storage.
>
> Add a founder decision section: authoritative statuses; pilot service; roles/task ownership; quote breakdown (WeQ4U fee vs authority/third-party/courier charges); payment milestones; document access/audit/retention. Prices can be decided later, but the system must be able to represent separate charge types and service-specific payment gates.
>
> Base44 is only being used to visualize and review the proposed experience. Do not describe Base44 as connected to the local application, as the live production database, or as a government integration. Do not invent service volumes, revenue, SLA targets, prices, approvals, or government partnerships. Use “to confirm” for unresolved rules. Provide a print/export-friendly page with no fake charts or sample operational figures.
